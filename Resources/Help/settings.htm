Settings Tab

The Settings Tab controls global directory paths, external map tile API access, and target display parameters for the in-game overlay map window. Proper configuration here is essential for scenario validation, add-on scenery database checks, and interactive map generation.

Map Tile Cache Info

In-game briefing and map overlay graphics are constructed using map tiles downloaded from OpenStreetMap (OSM). Map data is free to use for non-commercial applications, but requires registering with a tile provider to obtain an API key before graphics can be generated.

Attribution & Licensing: Map graphics rendered by this application contain data from OpenStreetMap and are used under the Open Database License (ODbL). All generated map overlay images incorporate mandatory © OpenStreetMap contributors copyright notices.

Local Tile Cache: Downloaded map tiles are saved locally in a dedicated cache directory. Reusing cached tiles for future scenario builds eliminates redundant network downloads, accelerates map rendering, and keeps your usage well within provider API rate limits.

Server / API key

Users of this program are required to register with the free OpenStreetMap (OSM) map tile provider Rapid to obtain an API key. This key is used to access map tiles from the server. The program will not work without a valid API key.

Follow these instructions to register with the OSM map tile server, obtain your API key, and store it on the Settings tab:

  1. Go to Rapid.
  2. Click on the Sign Up button in the top right corner and complete the registration process.
  3. Once registered, sign into the website.
  4. In the top search box labeled "Search APIs", type MapTiles and press Enter.
  5. Click on the result strictly titled MapTiles to open its API endpoint page.
  6. Select any endpoint from the left-hand menu (e.g., getStandardMapTile).
  7. Look at the Code Snippets panel on the right-hand side. Locate the line containing 'x-rapidapi-key: ...'.
  8. Use your mouse to highlight only the alphanumeric key string between the single quotes (or double-click the key text) and press Ctrl + C to copy it (e.g., 1234567890abcdef1234567890abcdef1234567890abcdef). Note: Do not click the copy icon on the code box, as this copies the entire cURL command.
  9. Click inside the Server / API key text field on the Settings tab of P3D Scenario Generator and paste your key. Validation occurs automatically when leaving the field.

Tip: Hovering your mouse cursor over the Server / API key field will expand a pop-up tooltip showing the full key string.

Cache Daily Total display field

Displays the total number of map tile requests performed during the current 24-hour cycle. Use this counter to monitor tile usage against provider rate limits.

Cache Usage display field

Displays the total local disk space consumed by cached map tile images saved in your user data directory.

Map Window Settings

The Map Window group specifies position, monitor routing, and frame dimensions for the in-flight overlay map window across single or multi-monitor display setups.

Monitor Number text box

Specifies the system display index where the map or briefing overlay window will render (e.g., 0, 1, or 2).

  • Display Indexing vs. Physical Layout: Index numbers correspond to how Windows enumerates connected displays (typically starting at 0), which does not always match physical ordering left-to-right or your designated "Primary" display. For instance, in a triple-monitor setup with your primary sim view centered, the far-left screen may be indexed as 0, center as 1, and right as 2.
  • Mixed Display Layouts: Adding displays above or below (such as a laptop screen underneath a center monitor) can shift index order further (e.g., top row 0, 1, 3 and bottom screen 2). Testing index numbers in test scenario builds helps confirm exact panel placement.
  • Safe Display Fallback: Setting the monitor index to 0 is always a safe baseline. If an invalid or disconnected monitor index is specified, the application automatically catches the error and renders the overlay safely on Monitor 0.

Offset text box

Specifies the margin padding (in pixels) applied between the map window edge and the monitor screen border.

Alignment combobox

Click the dropdown arrow to select screen anchor alignment for the map overlay (e.g., Top Right, Top Left, Bottom Right, Bottom Left, or Centered).

Monitor Width & Monitor Height text boxes

Enter the pixel resolution dimensions of your target display monitor (e.g., 1920 Width by 1080 Height) to calculate exact screen coordinates.

Window Size combobox

Click the dropdown arrow to select the square display window size in pixels (512 or 1024).

Zoom Level Generation Linkage: This selection directly controls the resolution density and the number of progressive tile zoom levels generated for the moving map display:

  • 512 × 512 Window: Generates 3 levels of zoom per flight leg (Zoom 1, 2, and 3).
  • 1024 × 1024 Window: Generates 4 levels of zoom per flight leg (Zoom 1, 2, 3, and 4), providing higher geographical resolution and broader spatial coverage.

Validation Rules: Leaving any field or changing a dropdown selection within this group automatically runs validation checks to ensure coordinates stay within valid display screen boundaries.

Overlay Window Handling & Operations

  • Single-Monitor Real Estate: Running a single display—particularly at resolutions below 1920×1080—will result in noticeable screen crowding when overlay windows are active.
  • Window Repositioning & Dragging: Panels must be undocked (showing a standard Windows title bar) to be moved cleanly. If a panel is currently docked within the main flight view, right-click the panel and select Undock Window. Attempting to drag docked panels can cause the mouse cursor to stick to the panel frame during repositioning.
  • Iterative Layout Tuning: Because display arrangements vary greatly, generating a quick test scenario helps fine-tune your preferred monitor index, window alignment, and margin offsets for your exact cockpit setup.

Moving Map Display & Controls

The In-Game Moving Map provides dynamic position tracking, heading updates, and leg route overlays across selectable zoom levels during active scenarios (3 or 4 levels depending on your configured Window Size).

Interactive Viewport Controls

  • Toggle Aircraft / Drag Mode: Click the Toggle Plane button on the map display to show or hide the aircraft symbol. Hiding the aircraft disables auto-tracking and unlocks manual panning, allowing you to click and drag across the map image.
  • Cycle Zoom Levels: Click the Cycle Zoom button to cycle the background chart through the generated tile zoom levels for the active flight leg (Zoom 1–3 for 512px windows, or Zoom 1–4 for 1024px windows).

Hardware & Cockpit Switch Bindings

In addition to the HTML buttons, moving map functions can be bound to physical cockpit switches, joystick buttons, or voice commands using mapped Prepar3D simulator variables:

Action Simulator Variable Function
Cycle Zoom A:ALTERNATE STATIC SOURCE OPEN Toggling this switch state cycles through Zoom levels 1, 2, and 3.
Toggle Aircraft Icon A:CABIN NO SMOKING ALERT SWITCH Toggling this switch toggles aircraft visibility and toggles manual mouse-drag mode.

Automated Tracking & Navigation Operations

  • Real-Time Tracking & Rotation: When the aircraft icon is toggled visible, the map viewport automatically centers on your aircraft's spatial coordinates (A:PLANE LATITUDE / A:PLANE LONGITUDE) and rotates the symbol to match true heading (A:PLANE HEADING DEGREES TRUE).
  • Automatic Leg Transitions: As you progress through scenario waypoints, the display monitors your active leg index (S:currentLegNo) and automatically updates background chart graphics (LegRoute_XX_zoomY.jpg) without requiring manual map reloads.

Application Storage & File Reference

Application configurations, runway spatial caches, system logs, and cached map tiles are stored locally on your system. Understanding these files makes it simple to back up user profiles, troubleshoot operational issues, or manage disk space.

Data Directory Structure (%APPDATA%\P3D Scenario Generator\)

  • ui_settings.json & ui_settings.json.bak: The primary application configuration profile and its automatic backup copy. Beyond system folder paths and RapidAPI credentials, this file persists control states for every scenario mode (Circuit, Photo Tour, Sign Writing, Celestial, Wiki List), multi-monitor overlay window positioning metrics, and dynamic, aircraft-specific circuit pattern profiles (such as speeds, leg lengths, and altitudes keyed to individual aircraft titles).
  • runways.xml: The master XML airport and runway database file. Placing a custom XML database here (such as one compiled using Pete Dowson's MakeRunways) overrides the built-in stock airport database to enable scenario builds at custom add-on airfields. For step-by-step instructions on generating and installing this file, see General Tab: Including Add-on Scenery Runways.
  • runways.cache: A binary cache file generated automatically on initial XML load. It stores the deserialized runway object structure alongside a spatial KD-tree index, drastically bypassing XML parsing overhead to accelerate application startup. Rebuilt automatically whenever runways.xml is updated or deleted.
  • AircraftVariantsJSON.txt: Stores user-configured aircraft profiles in JSON format. Each variant entry contains the internal simulator title (Title), friendly UI label (DisplayName), cruise speed in knots (CruiseSpeed), local image preview path (ThumbnailImagePath), and gear capability flags (HasFloats and HasWheelsOrEquiv). The generator parses these attributes to calculate estimated flight durations and filter suitable landing surfaces (water vs. hard runways). For details on adding, renaming, or deleting aircraft profiles in the UI, see General Tab: Aircraft Selection.
  • LocationFavouritesJSON.txt: Stores user-defined geographic filter presets used on the General tab. Each preset entry contains a preset title (Name) alongside string arrays defining target Countries, States, and Cities (or set to ["None"] to leave unconstrained). The scenario generator uses these region rules to filter valid departure airports and destination waypoints during generation. For instructions on creating and managing geographic filter presets in the UI, see General Tab: Location Filter.
  • InfoLog.txt, WarningLog.txt & ErrorLog.txt: Operational execution logs tracking application runtime events, status updates, non-fatal warnings, and detailed error stack traces for troubleshooting.
  • Exported Scenarios (<Scenario Base Folder>\<Scenario Title>\): Output destination designated in Folder Info settings containing compiled Prepar3D flight packages (.fxml, .xml) and map briefing graphics.

Tile Cache Directory (%APPDATA%\P3D_Scenario_Generator_Cache\)

  • Zoom Level Folders (\3\ through \18\): Subdirectories organized by standard OpenStreetMap zoom levels containing tile grid image files (`.png`). Deleting these folders is completely safe and reclaims local disk space—missing tiles automatically re-download on future scenario builds.
  • cache_stats.json: Stores runtime cache analytics and daily tile request counters. The application parses this file to populate the Cache Daily Total and Cache Usage display fields on the Settings tab.
